# SA-PASS alignment library (`Alignment/`)

SA-PASS checks that each Lean theorem of the trusted library `NetworkEpi.*` says what its
natural-language source text says. This is the procedure of `../../SA-PASS_SKILL.md`, which was
written for the TemporalOlog project, adapted to this repository. The `Alignment` library is **not
trusted code**. It is a separate `lean_lib` and not a default target, so `lake build` still builds
only the trusted library.

| TemporalOlog | here |
|---|---|
| trusted library `TemporalOlogs.*` | `NetworkEpi.*`: the root module `NetworkEpi`, exactly the modules imported by `NetworkEpi.lean` (read from disk), plus their `NetworkEpi.*` imports. Trust is decided by module, never by declaration name. |
| spec `kernel.md`, ADRs | theorem docstrings (the **Design statement** quote from `DESIGN_NetworkEpiCore.md` and the **Lean statement** paragraph of every citable theorem), module header text and tables, `../README.md` |
| `docs/alignment/claims.yaml` | fragments `Alignment/claims/<Group>.yaml`, merged into `Alignment/claims.yaml` |
| `lean/Alignment/DataTypes.md` | `Alignment/DataTypes/<Group>.md` |
| K31 worked example | `Alignment/Example/ExampleShadows.lean`, `ExampleChecks.lean` |

There is one group per trusted module, named after its path without dots (`DynBasic`,
`DynProducts`, `SyntaxRxn`, `SemanticsEB`, `SemanticsMA`, `SemanticsPWS`,
`SemanticsPoissonSIR`, and later WP28's `Morphisms…` and `Closure…`). Claims taken from
`../README.md` form the group `Docs`. Claim ids are `<Group>.<lowerCamelTheoremName>` (split
into `…a`, `…b`, … when a docstring makes several claims). Ids must match `[A-Za-z0-9._-]+`.
The prefixes `EXAMPLE.` and `SELFTEST.` are reserved. Register a claim for every name in
`../CITABLE.txt` first.

## Roles (use different agents)

1. **Registrar** writes `Alignment/claims/<Group>.yaml`. Each entry has the fields `id, group,
   source {file (relative to proofs/), lines 'a-b'}, text, kind, impl, supporting, impl_note,
   required, status, notes`. The `text` is a verbatim quote with whitespace normalised. Separate
   non-adjacent fragments with a line containing only `[...]`. Set `required: true` iff
   `status: implemented`. The `status` is one of `implemented | axiomatized | missing | informal`.
   For an `axiom`, list the axiom as `impl` (the audit then reports `impl_unsound`).
2. **Blind shadow author** writes `Alignment/Shadows/<Group>.lean`. This author reads **only**
   the claim's entry in `Alignment/claims_blind.yaml`, `Alignment/DataTypes/<Group>.md`, this
   README and `Example/ExampleShadows.lean`, plus the cited `.md` passage for `Docs` claims. The
   author never opens `NetworkEpi/**/*.lean` (the statement sits right under the docstring),
   `claims.yaml`, checker files or reports, and never greps for theorem names.
3. **Checker author** may read everything. They write `Alignment/Checks/<Group>.lean`, which
   contains the `sa_claim` registrations, the bridges, the checkers and the failure records. They
   add both modules to `All.lean`.
4. **Bridge reviewer** (independent) writes records only in `Alignment/ReviewedBridges.lean`.
5. **Triage / remediation**: follow SA-PASS_SKILL.md §6. Never adapt a shadow to the
   implementation and never weaken a trusted theorem.

## Commands (from `NetworkEpiCore.jl/proofs`; wrap long ones in `perl -e 'alarm 500; exec @ARGV'`)

```sh
bash scripts/sa_pass.sh                  # merge claims, build, audit, report (Alignment/report/sa_pass_report.md)
bash scripts/sa_pass.sh --self-test      # every mock gets exactly its expected status; EXAMPLE.* pass
bash scripts/sa_pass.sh --strict         # exit 1 if a required claim lacks SA-PASS = 1
bash scripts/sa_pass.sh --no-build       # re-score the last audit JSON
bash scripts/sa_pass.sh --check-sources  # also check each claim text against its cited lines
perl -e 'alarm 500; exec @ARGV' lake build +Alignment.Shadows.<Group>   # one module
perl -e 'alarm 500; exec @ARGV' lake build +Alignment.Checks.<Group>
lake build                               # trusted library only
```

While you write checkers, you can put `#sa_audit "<id>"` temporarily at the end of a Checks file.
It logs that claim's audit as JSON. Review records are invisible there, so every bridge shows as
`unreviewed`. Remove the command before you finish. Re-run the self-test whenever you change
`Audit.lean`, and port every new bypass into `Example/SelfTest.lean`.

## Vocabulary (`Alignment.Registry`)

```lean
@[sa_reference "c"]     def T  : Prop := …       -- intended statement
@[sa_shadow "c" i]      def Si : Prop := …       -- i = 1 … n, one atomic requirement each
@[sa_ref_forward "c" i] theorem … : T → Si        -- any tactics, must be sorry-free
@[sa_complete "c"]      theorem … : S1 → … → Sn → T
@[sa_bridge "c"]        theorem … : ∀ xs, f xs ↔ Q xs      -- or ∀ xs, f xs = g xs
@[sa_forward "c" i]     theorem … (h : sa_impl% "c") : Si
@[sa_backward "c"]      theorem … (s1 : S1) … (sn : Sn) : sa_impl% "c"
sa_claim "c" group "G" required text "…verbatim registry text…" impl Thm₁ Thm₂
sa_fail_forward "c" i "reason"      sa_fail_backward "c" "reason"   -- "SHADOW?: …" if the shadow misreads
sa_bridge_reviewed Decl "<hash>" "<reason>"    sa_bridge_rejected Decl "<reason>"
@[sa_witness "c" i]     theorem … : ∃ x₁ … xₖ, True   -- hypotheses of the i-th impl can hold; any tactics
@[sa_refutation]        theorem … : ∀ ys, P₁ ys → … → False  -- (or → ¬ P ys, → a ≠ b); global refuter
sa_shadow_reviewed Decl "<hash>" "<reason>"    -- reviewer only, in ReviewedBridges: accepts a trusted-free shadow
```

* `sa_impl% "c"` is the type of the `impl` theorem. With several `impl`s it is their
  right-nested conjunction, in `sa_claim` order. Level parameters are kept.
* The `text` of `sa_claim` must equal the registry text after whitespace normalisation. Write
  fragments as `"A. [...] B."`. Escape `"` and `\` in the Lean string.
* `required` must equal the registry's `required`. `group` must equal the registry group.
  `sa_claim` must be in `Alignment.Checks.<group>`, and shadows and certificates in
  `Alignment.Shadows.<group>`.

## What the audit checks

**Registration (any flag scores the claim 0).** The Lean side: `invalid_id`, `duplicate` (claim,
checker or certificate registered twice, or a checker together with an `sa_fail` record), `gap`
(no `impl`), `impl_untrusted` (unknown, not a theorem, or not in a trusted module),
`impl_unsound` (an axiom, or `collectAxioms` beyond `propext, Quot.sound, Classical.choice`, which
includes `sorryAx`), `shadow_mismatch` (reference or shadow not a `def … : Prop`, more than one
reference, indices not `1..n`, a declaration registered twice, attribute applied outside the
declaring module, wrong module), `incomplete` (missing or ill-typed `T → Sᵢ` / `S₁ → … → Sₙ → T`,
certificates with sorry or non-standard axioms), `module_mismatch`, `audit_error`, and the
`shadow_trusted_free`, `hypothesis_refuted` and `witness_invalid` flags described below. The registry
side (`sa_pass_score.py`): `unlisted`, `impl_mismatch` (set comparison), `text_mismatch`,
`group_mismatch`, `required_mismatch`, `duplicate`, `invalid_id`, `gap`.

**Statements.** A forward checker's type must be syntactically `T̂ → Sᵢ`. `T̂` is exactly
`sa_impl%`, and `Sᵢ` is the shadow constant with distinct universe parameters. A backward
checker's type must be syntactically `S₁ → … → Sₙ → T̂`. Anything else is `fail`.

**Structural rule** (for forward and backward proofs). The audit walks the proof value with
types. Types and propositions are statements and are not judged. Proofs are judged. Proofs that
are arguments of data terms (e.g. `Semiconj.ofIsSemiconj π h`) are skipped, because by proof
irrelevance they carry no content unless extracted. Constants declared in the alignment library
are *inlined*, i.e. their values are walked; this covers helper lemmas and definitions, other
checkers, certificates, `match_`/`proof_`/`_private` auxiliaries, and theorems falsely registered
as shadows. Only registered `def … : Prop` shadows and references, and bridges, are not
inlined. Every remaining constant must be one of:

* (a) in `coreLogicWhitelist`: `And.{intro,left,right,elim,imp,symm,rec,casesOn}`,
  `Iff.{intro,mp,mpr,refl,rfl,symm,trans,of_eq,rec,casesOn}`,
  `Or.{inl,inr,elim,imp,symm,resolve_left,resolve_right,rec,casesOn}`,
  `Exists.{intro,elim,imp,rec,casesOn}`, `Eq.{refl,symm,trans,mp,mpr,rec,ndrec,casesOn,subst,substr}`,
  `rfl`, `congrArg`, `congrFun`, `congr`, `cast`, `HEq.{refl,rec,casesOn,ndrec}`, `eq_of_heq`,
  `heq_of_eq`, `funext`, `propext`, `Not`, `Not.{intro,elim}`, `mt`, `absurd`,
  `False.{elim,rec,casesOn}`, `True.{intro,rec,casesOn}`, `trivial`, `id`, `Function.comp`,
  `Function.const`;
* (b) a *data* constant, meaning its type is not a proposition (definitions, types, instances,
  data constructors, recursors of plain data), EXCEPT `Classical.*`, `Decidable.*` (so no
  `decide`, `Decidable.casesOn` or `byCases`), `sorryAx`, `Lean.ofReduce*`, `Lean.reduce*` and
  `Lean.trustCompiler`, the proof carriers `PLift`/`PProd`/`PSigma`, eliminators of data
  inductives that have proof fields (`Subtype`, `Fin`, `Semiconj`, …), and projections of data
  structures in a proof position (`m.diff` for `m : Semiconj A B`, `Subtype.property`, `Inhabited.default` of a
  Prop, …);
* (c) the claim's own reference and shadows (and other claims' shadows, which are also Props);
* (d) a bridge registered for **this** claim with status `reviewed`;
* (e) an auto-generated equation or unfolding lemma `f.eq_N`, `f.eq_def` or `f.eq_unfold` (these
  names are reserved), so `unfold f` and `rw [f]` are fine;
* (f) the introduction, elimination and projection rules of Prop-valued inductives and structures
  declared in `NetworkEpi.*` or `Alignment.*` (their definitional logic);
* (g) a Prop-valued typeclass instance (instances appear in statements).

Any other constant is reported with its reason, and the check is `audit_violation`. The report
lists the offending constants. This includes library theorems, the implementation theorem used
outside `h`, trusted lemmas and all `simp`/`ring`/`omega`/`linarith`/`norm_num`/`decide`
artefacts. `sorryAx` gives the status `sorry`. Every checker, bridge and certificate proof is
also re-checked by the kernel.

**Vacuity guard** (forward checks). The audit first normalises `proof h`. Normalisation does β
and ζ reduction, inlines alignment helpers, and unfolds `id`, `Function.const`, `Function.comp`,
`flip`, `inferInstance(As)`, matchers, `Or.elim`, `Exists.elim` and `And.elim`. It reduces
projections of constructors and ι-redexes, drops `Eq.mpr`/`Eq.mp`/`cast` between
definitionally equal types, and replaces a case split on a proof whose branches ignore the fields
by its branch. The check is `vacuous` if, after this: (i) `h` does not occur; or (i′) `h` occurs
only in types or in proofs inside data; or (ii) the kernel accepts the proof after `h : T̂` is
replaced by `h : P` for a fresh `P : Prop`, with every proposition subterm definitionally equal to
`T̂` also replaced by `P`, at type `P → Sᵢ`.

**Vacuity guard** (backward checks). The audit normalises `proof s₁ … sₙ` in the same way. The
check is `vacuous` if (i) no shadow binder `sᵢ` occurs in a proof-relevant position, or (ii) the
kernel accepts the proof after every `sᵢ : Sᵢ` is replaced by `sᵢ : Pᵢ` for fresh `Pᵢ : Prop`
(every proposition subterm definitionally equal to `Sᵢ` is also replaced), at type
`∀ P₁ … Pₙ, P₁ → … → Pₙ → T̂`. A passing backward check that leaves some shadows unused gets the
hint `backward_unused_shadows` (they may be redundant given the others); it is not scored. If the
normaliser exhausts its budget, both tests run on the unnormalised proof and the hint
`backward_guard_unnormalised` is added (limitation 13).

**Content-free shadows** (`shadow_trusted_free`, scores 0). A shadow whose statement mentions no
constant of a trusted module, after inlining every alignment-library declaration it uses, is a
closed statement of logic or arithmetic: an implementation that restates it passes whatever the
text says. The flag is lifted only by an independent `sa_shadow_reviewed <shadow> "<hash>"
"<reason>"` record in `Alignment.ReviewedBridges`, for claims whose text is itself arithmetic.
The hash is a content hash of the shadow and of every alignment helper it inlines (printed in the
report); a record with another hash is `stale`.

**Refutable hypotheses** (`hypothesis_refuted`, scores 0). The refuters are the sound theorems of
the trusted library, and the alignment-library `@[sa_refutation]` theorems (sound, kernel
re-checked), of the shape `∀ ys, P₁ ys → … → Pₘ ys → False`, where the conclusion may also be
`¬ P ys` or `a ≠ b`. For every implementation theorem the audit matches each refuted premise
`Pⱼ` against a hypothesis of the implementation (by unification; all of `ys` must be determined),
builds the refutation `∀ x₁ … xₖ, False` of a prefix of the implementation's binders, and has
the kernel check it. A refuted implementation is vacuously true, and so is every shadow that
shares the hypothesis. The report lists every refuter and its status.

**Satisfiability witnesses** (`witness_missing` hint, `witness_invalid` scores 0). When a
hypothesis of the `i`-th implementation theorem is headed by a trusted-library predicate that
every shadow also mentions, nothing in the checks shows that the hypothesis can hold. An
`@[sa_witness "c" i]` theorem in the claim's Checks module proves `∃ x₁ … xₖ, True` over the
implementation's binders up to its last hypothesis (use the implementation's universe names;
any tactic may be used, it must be sorry-free). The kernel checks its proof against that exact
statement; otherwise the flag `witness_invalid`. Without a witness the claim gets the hint
`witness_missing`. See `EXAMPLE.roundTrip`.

**Bridges.** A bridge's statement must be `∀ xs, f xs ↔ Q xs` (or `f xs = true ↔ Q xs`) or
`∀ xs, f xs = g xs`, where `f` is a *definition of a trusted module* applied to distinct bound
variables. The right-hand side, and every top-level conjunct of an `↔` right-hand side, must
mention a bound variable. The bridge must be a theorem in the alignment library. It must not be,
or depend transitively on, any claim's implementation theorem. It must be sorry-free and
kernel-checked. The statuses are:

* `reviewed`: a record in `Alignment.ReviewedBridges` whose hash equals the stable statement hash.
  The hash is printed in the report and is FNV-1a of a canonical serialisation, independent of
  binder names.
* `stale`: a record exists but the hash differs, e.g. because the statement changed.
* `unreviewed`: there is no record. Records written in any other module are ignored and listed
  as warnings.
* `rejected`: an `sa_bridge_rejected` record exists.
* `invalid`: the bridge breaks one of the rules above.

Only `reviewed` bridges may be used, and only by checkers of the claims they are registered for.

**Statuses and scores.** Each check is `pass | fail | vacuous | audit_violation | sorry | missing`.
With n shadows, SA-PASS = 1 iff the registration is consistent, n ≥ 1, every forward check
passes and the backward check passes. `SA-PASS_soft = ½·(forward passes)/n + ½·[backward pass]`,
and 0 when inconsistent. The report gives overall and per-group counts, the required failures,
bridges by status, offending constants, recorded failures (with `SHADOW?:` marked), and
`identical_to_impl` (shadows that are literally `T̂`: weak evidence).

## Template: `Alignment/Shadows/<Group>.lean` (blind)

```lean
import Alignment.Registry
import NetworkEpi.<Module>          -- only for the data types / operations listed in DataTypes

open NEP

namespace Alignment.Shadows.<Group>.<ClaimSlug>

/-- Membership of a T_net type in T_EB = {contact, exit, progress, remove}, in primitive terms. -/
def InTEB (t : TNet) : Prop := t = .contact ∨ t = .exit ∨ t = .progress ∨ t = .remove

-- the text is an iff: one shadow per direction
@[sa_reference "<Group>.ebAdmissibleIffType"]
def T : Prop := ∀ {σ : Type} (r : NRxn σ), r.EBAdmissible ↔ InTEB r.type
@[sa_shadow "<Group>.ebAdmissibleIffType" 1]
def S1 : Prop := ∀ {σ : Type} (r : NRxn σ), r.EBAdmissible → InTEB r.type
@[sa_shadow "<Group>.ebAdmissibleIffType" 2]
def S2 : Prop := ∀ {σ : Type} (r : NRxn σ), InTEB r.type → r.EBAdmissible
@[sa_ref_forward "<Group>.ebAdmissibleIffType" 1] theorem ref_fwd1 : T → S1 := fun t _ r => (t r).mp
@[sa_ref_forward "<Group>.ebAdmissibleIffType" 2] theorem ref_fwd2 : T → S2 := fun t _ r => (t r).mpr
@[sa_complete "<Group>.ebAdmissibleIffType"]
theorem complete (s1 : S1) (s2 : S2) : T := fun r => ⟨s1 r, s2 r⟩

end Alignment.Shadows.<Group>.<ClaimSlug>
```

Every shadow must be falsifiable by a wrong implementation. Split along conjunctions, the two
directions of an iff, and the readings of an ambiguity. See `Example/ExampleShadows.lean`
(`EXAMPLE.admissibleType`, `EXAMPLE.notAdmissible`, `EXAMPLE.roundTrip`).

## Template: `Alignment/Checks/<Group>.lean`

```lean
import Alignment.Registry
import Alignment.Shadows.<Group>

open NEP

namespace Alignment.Shadows.<Group>.<ClaimSlug>

sa_claim "<Group>.ebAdmissibleIffType" group "<Group>" required
  text "EB-admissibility is membership of the reaction's type in T_EB: \"the sub-theory with no arrow into Sus\" (DESIGN §B.2)."
  impl NEP.NRxn.ebAdmissible_iff_type

/-- Bridge (needs independent review): our `TNet.inTEB t = true` vs the text's notion. -/
@[sa_bridge "<Group>.ebAdmissibleIffType"]
theorem bridge_inTEB (t : TNet) : TNet.inTEB t = true ↔ InTEB t := by
  cases t <;> simp [TNet.inTEB, InTEB]      -- tactics are allowed in bridges only

@[sa_forward "<Group>.ebAdmissibleIffType" 1]
theorem fwd1 (h : sa_impl% "<Group>.ebAdmissibleIffType") : S1 :=
  fun r hr => (bridge_inTEB r.type).mp ((h r).mp hr)
@[sa_forward "<Group>.ebAdmissibleIffType" 2]
theorem fwd2 (h : sa_impl% "<Group>.ebAdmissibleIffType") : S2 :=
  fun r ht => (h r).mpr ((bridge_inTEB r.type).mpr ht)
@[sa_backward "<Group>.ebAdmissibleIffType"]
theorem bwd (s1 : S1) (s2 : S2) : sa_impl% "<Group>.ebAdmissibleIffType" :=
  fun r => ⟨fun hr => (bridge_inTEB r.type).mpr (s1 r hr), fun ht => s2 r ((bridge_inTEB r.type).mp ht)⟩
-- if a check is genuinely false:  sa_fail_forward "<Group>.<id>" 2 "impl assumes μ ≠ 0; text says nothing"

end Alignment.Shadows.<Group>.<ClaimSlug>
```

The review record goes in `ReviewedBridges.lean`, written by the reviewer:
`sa_bridge_reviewed Alignment.Shadows.<Group>.<ClaimSlug>.bridge_inTEB "<hash from report>"
"<source: why the RHS is exactly the text's notion>"`.

Writing structural proofs:

* Use `intro`, `exact`, `constructor`, `refine ⟨_, _⟩`, `obtain`/`rcases`/`match`, `show`/`change`,
  `unfold`, `rw [h …]`, `rw [bridge]`, `Eq.trans`/`Eq.symm`/`congrArg`, `funext` and `rfl`.
  Definitional unfolding is free, so `exact h x` against a goal that is definitionally equal is fine.
* Do not use `simp` (even `simp only`, which adds `of_eq_true`/`eq_self`), `ring`, `linarith`,
  `omega`, `norm_num`, `decide`, `positivity`, `by_cases`/`by_contra` (Classical), library lemmas
  (`le_of_eq`, `mul_comm`, …) or proof fields of data (`m.diff`, `m.comm`). If text and implementation
  differ only algebraically, write a bridge. If they really differ, record `sa_fail_*`.
* When the goal is a shadow constant with implicit or instance binders, use `intro` rather than
  `fun`.
* For universe-polymorphic `impl`s (none in NetworkEpi yet), declare the implementation's own
  level names (`universe u_1 u_2`; see `#check @Thm`) and state `S1.{u_1, u_2}`.

## Known limitations of the audit

1. Kernel computation and induction count as structural. `rfl`/`Eq.refl` on closed computable
   terms (ℕ, and ℚ via the kernel's GMP arithmetic), `Nat.rec` and matches on plain data are all
   allowed. A shadow that is provable this way from scratch passes whenever the checker also uses
   `h` relevantly: the vacuity guard detects non-use, not partial use.
2. The vacuity guard does not evaluate decidable case splits. An `if`/`dite` whose dead branch is
   the only use of `h` is not detected. Library functions that discard an argument are detected
   only through test (ii), and only when the discarded argument's type mentions `T̂` up to
   definitional equality.
3. Proof carriers are enumerated (`PLift`, `PProd`, `PSigma`, `Decidable`, projections of data
   structures in proof positions, eliminators of data with proof fields). An exotic library data
   constant that stores a proof in some other way could still smuggle one. Port any such case into
   the self-test.
4. The bridge rule "no closed component" looks only at top-level conjuncts. Theorem content
   hidden inside a conjunct that mentions a bound variable must be caught by the reviewer.
5. Blindness and review independence are procedural. `identical_to_impl` is the only automatic
   hint.
6. Meta-programs in alignment files (raw `addDecl`, writing the environment extension,
   `debug.skipKernelTC`) are out of scope. Two defences exist: registry module fields are
   replaced by the actual exporting module, and all checker, bridge and certificate proofs are
   re-checked by the kernel.
7. Trust follows `NetworkEpi.lean`. Adding an import there makes a module trusted, which is a
   trusted-library change. Upstream (Mathlib/core) constants are judged only by their types.
8. Constants inside statements are never judged. This is deliberate: statements such as
   `Semiconj.ofIsSemiconj π h` contain proofs.
9. Each checker and bridge gets a fresh heartbeat budget. Exhausting it gives `audit_violation`
   with `<audit error: …>`. The normaliser has a fuel limit (`<vacuity guard could not decide>`).
10. `shadow_trusted_free` is syntactic. A shadow that mentions a trusted constant trivially
    (`… ∧ CNet = CNet`) is not flagged; blind authors must not do this.
11. Refutation is only as strong as the refuters. The audit finds a vacuous hypothesis only
    when a trusted or `@[sa_refutation]` theorem refutes it, premise by premise (greedy
    matching, no search over combinations). An unsatisfiable hypothesis that nothing refutes
    shows up at best as the hint `witness_missing`, which is reported but not scored.
12. The backward vacuity guard requires at least one shadow to be used. A backward checker that
    uses one shadow and discards the others passes, with the hint `backward_unused_shadows`.
13. When the normaliser exhausts its budget on a backward proof (it can blow up on deep
    destructuring of existentials with instance arguments), the backward guard runs both tests
    on the unnormalised proof and adds the hint `backward_guard_unnormalised`. That check does
    not see through dodges such as destructuring a shadow and ignoring its parts; read such
    checkers by hand. The forward guard still reports an undecided case as `audit_violation`.

## Port notes (NetworkEpiCore.jl)

- **Upstream.** This harness is `EdgeBasedModels.jl/proofs/Alignment`, as hardened by WP4.
  `scripts/sa_sync_harness.py` re-copies the shared files and reapplies the adaptations below.
  Re-run the self-test after every sync.
- **Adaptations.**
  - The trusted root is `NetworkEpi`: the root module itself (it is built by the `NetworkEpi`
    library), the modules imported by `NetworkEpi.lean` and their `NetworkEpi.*` imports.
  - Everything else in `Audit.lean`, `Registry.lean` and the scripts is upstream code.
- **Worked example.** `EXAMPLE.admissibleType` needs a reviewed bridge, `EXAMPLE.notAdmissible`
  has two implementation theorems, and `EXAMPLE.roundTrip` has an `@[sa_witness]` certificate.
- **Self-test.** Every upstream mock is ported with NetworkEpi constants, with two exceptions:
  - `SELFTEST.refutedHypothesis` is not ported. A sound refuter can only refute an
    unsatisfiable hypothesis, and NetworkEpi has no trusted theorem with one, by design. The
    refuter-validity mocks are kept. `SELFTEST.witnessMissing` has valid refuters headed by
    `NRxn.EBAdmissible` in scope, so it doubles as the no-false-positive control.
    Re-checked after the WP13 review: an earlier `conservation` asked for a *global* solution,
    which some models lack (EB SEIR on Poisson(5) blows up backward in finite time), so for
    those models its hypotheses could not be met. The solution theorems now take solutions on a
    time interval `I ∋ 0`. `NEP.exists_local_solution` proves that a solution on some
    `(−ε, ε)` exists for every T_EB model whose ψ, ψ', ψ'' are C¹ at the initial θ, and
    `NEP.conservation_local` shows all hypotheses of `conservation` met together.
  - The witness mocks are monomorphic, because NetworkEpi has no universe-polymorphic theorem.
- **Limitation found while porting.** Vacuity test (ii) replaces every subterm definitionally
  equal to the shadow (or to `T̂`) by the fresh proposition. So when a shadow is definitionally
  equal to `T̂`, a checker that discards its shadow is **not** detected: an earlier version of
  `SELFTEST.backwardVacuousEval` passed. The mocks therefore use shadows that differ from `T̂`,
  and such shadows are flagged only as `identical_to_impl` (weak evidence).
- **Citable theorems.** SA-PASS claims are to be registered for the names in `../CITABLE.txt`.
  Their docstrings carry a **Design statement** (a quote from DESIGN_NetworkEpiCore.md) and a
  **Lean statement** (the precise natural-language spec).
